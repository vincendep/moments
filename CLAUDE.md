# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Moments is a private SwiftUI iOS app (iOS 17+, iPhone only) for keeping multiple timelines of photos, videos, notes and voice memos. Any entry can be a milestone; a milestones view shows them on a line with the time between them. No third-party dependencies and no tests yet.

## Build

The Xcode project is generated by XcodeGen from `project.yml` at the repo root. Edit `project.yml` for target settings, Info.plist keys (mostly `INFOPLIST_KEY_*` build settings; `Moments/Info.plist` and `Moments/Moments.entitlements` are generated from its `info:` and `entitlements:` sections) and permission strings, then regenerate. Don't hand-edit `Moments.xcodeproj`. New Swift files under `Moments/` are picked up on regeneration. The app version is `MARKETING_VERSION` and the build number `CURRENT_PROJECT_VERSION` in `project.yml` (raise the build for every App Store upload); the timeline settings screen shows both at the bottom.

```bash
xcodegen
```

```bash
xcodebuild -project Moments.xcodeproj -scheme Moments -destination 'generic/platform=iOS Simulator' build
```

The camera needs a real device; on the simulator `CameraView` falls back to the photo library. For location, set one with `xcrun simctl location <device> set <lat>,<lon>`; `xcrun simctl privacy <device> reset location it.vincendep.moments` brings the consent prompt back.

iCloud sync needs a paid team: `DEVELOPMENT_TEAM` and the bundle ID in `project.yml` are the owner's (change both to build under another account) (the CloudKit container is `iCloud.$(PRODUCT_BUNDLE_IDENTIFIER)`). Simulator builds work without a team; without an iCloud account the store just stays local (the log shows `CKAccountStatusNoAccount`).

## Architecture

SwiftData holds two models: `Timeline` (name, settings) with a cascading to-many `entries` relationship to `Entry`. The store syncs to the user's private iCloud database through CloudKit (the default `ModelConfiguration`, `.automatic`, picks up the entitlement), so a new phone gets everything back. Media:

- **Photos/videos** are saved to the system Photos library via `PhotoService`, never copied into the app. `Entry.assetLocalID` is the `PHAsset` ID on the device that added it; `assetCloudID` (`PHCloudIdentifier`) is the same on every device with iCloud Photos. Always get an asset's ID through `PhotoService.localID(for:)`, which falls back to the cloud ID and never writes back (each device has its own local IDs). Importing from the library links existing assets, using the asset's creation date as the entry date.
- **Voice memos** are recorded to a temp file by `AudioService` and stored in `Entry.audioData` (`.externalStorage`), so they sync with the store.
- **Titles, notes and metadata** live in SwiftData.

Things to keep in mind:

- Which Photos album new media goes into is a per-timeline setting stored on `Timeline` (`albumModeRaw` with a computed `albumMode: AlbumMode` — `.perTimeline` / `.shared` / `.none` — plus `addImportsToAlbum`). `PhotoService.album(for:)` resolves the album; per-timeline album IDs are kept per device in `UserDefaults` (`PhotoService.albumID(for:)`, keyed by `Timeline.uuid`), because a synced local ID would make devices overwrite each other; another device finds the album by title, as it arrives through iCloud Photos. Albums are renamed with the timeline.
- Every entry kind has a `title` (optional; `displayTitle` falls back to `dateLabel`) and `text`, shown as Notes (the whole content for note entries). Time of day is optional: when `hasTime` is false, `date` is kept at the start of the day (`DateTimeSection` enforces this).
- Location: `Entry.latitude`/`longitude`/`placeName`, read and set together as `Entry.place` (`Models/Place.swift`). The system consent prompt is the only switch, with no in-app setting: `TimelineView.present(_:)` asks once (`LocationService.requestAccess()`) before the first capture sheet opens, and with access new notes, voice memos and camera captures get the current place (`LocationService.current()`, reverse-geocoded by `CLGeocoder`); camera captures also write it to the Photos asset, since the system camera picker saves none. Library imports never use the current location: they take `PHAsset.location`, named after inserting. `LocationSection` (small map plus the name, or "Add Location") is on every entry's details and in the note and voice editors; it pushes `LocationPicker` (Apple Maps search via `MKLocalSearchCompleter`, "Current Location" only with access, "Remove Location"), so places can be added without location access. Rows don't show the place.
- Milestones: `Entry.isMilestone`, toggled by the ribbon button in `EntryDetailView`'s toolbar (outlined in red, filled in marigold when on) or by a leading swipe on a row. The list only flags milestone rows (and `DayScrubber` dots milestone days); `EntryDetailView` has no list of other milestones. Helpers (`Timeline.milestones`, oldest first, and the elapsed strings) are in `Models/Milestones.swift`. Once a timeline has a milestone, `TimelineView` shows "All | Milestones" album divider tabs (`AlbumTabs`); the Milestones view lists only milestones, without month headers or scrubber, each row with its full date and the time since the first milestone (`Entry.sinceFirstMilestone(_:)`, passed to `EntryRow` as `elapsed`). A `MilestoneRail` marigold thread joins them, pinned at each milestone, and between each pair the time between them is handwritten in `.pencil` beside an hourglass (`Entry.interval(since:)`); its rows use `milestoneRailRow()` (no vertical insets or separators) so the line is unbroken, and delete by trailing swipe since the interval rows rule out `onDelete`.
- `Entry.kind` is persisted as `kindRaw: String` with a computed `EntryKind` wrapper. CloudKit rules apply to the models: every property needs a default or must be optional, relationships must be optional, and no `@Attribute(.unique)`. Entries have a stable `uuid` and `modifiedAt` (set on edit), groundwork for merging timelines from another person via export/import.
- `PhotoService.backfillCloudIDs(in:)` runs on launch once Photos access is granted, since a fresh capture only gets an iCloud ID once it reaches iCloud.
- On first launch `RootView` creates a default "My Timeline" (guarded by the `"seededDefaultTimeline"` `@AppStorage` flag, so it isn't recreated after the user deletes it). On a new phone it is created before iCloud delivers the user's timelines, so `removeRedundantDefaultTimeline()` deletes it while untouched once older timelines appear.
- Navigation: `RootView` shows the current timeline full screen (`"lastTimelineID"` `@AppStorage`, matched against `Timeline.uuid`, falling back to the first). There is no list screen: the navigation title's menu (`toolbarTitleMenu`, which needs an inline title) switches timelines and offers "New Timeline…". The gear opens `TimelineEditorView`, the single per-timeline screen for name, media settings and deletion (it also creates timelines). `TimelineView` groups entries by month, always newest first, and opens at the top; the Milestones view is the opposite, oldest first, so it reads from "Start". `DayScrubber` on the right edge jumps to any day with entries (days spaced evenly, year labels); it fades in while scrolling, detected with a simultaneous `DragGesture` on the `List` since iOS 17 has no scroll-offset callback, and jumps via `ScrollViewProxy`. It presents the capture sheets from a bottom-center floating add button. Each capture view takes the timeline and inserts its own `Entry`. Tapping a row pushes `EntryDetailView`, which shows the media (full photo, `VideoPlayer`, voice playback) and edits title, notes and date/time in place via `@Bindable`, saving on disappear. `TitleSection` (title field with the date as placeholder), `DateTimeSection` and `LocationSection` are shared by it and `NoteEditorView` (the last two also by `VoiceRecorderView`).
- Design system ("The Family Album": album paper, white prints, darkroom red; mockups at https://claude.ai/artifact/8HkXzsDHQu1B7kAqf8udyk; the older token reference at https://claude.ai/artifact/9zbESFb8q5AHoCbwrgW3rb predates it). `Views/Theme.swift` holds the colours (asset-catalog sets with a darkroom-brown dark mode: `.darkroom` accent, `.darkroomFill`, `.marigold` for milestones only, `.postmark` for places, `.pencil` for margin notes, `.paper`, `.card` (print white), `.ink`, `.tab`, `.rule`, `.dateStamp`, `.shadow`, `.onDarkroom`) and fonts; never hard-code a colour or point size, and use `.shadow` (never `.ink`) for shadows so dark mode doesn't glow. Fonts are bundled in `Moments/Fonts` (SIL OFL, licences beside them, registered via `UIAppFonts` in `project.yml`) and reached through `AlbumFont`, which scales with Dynamic Type: Fraunces (soft, regular weight) only for headings (timeline name in the nav bar, italic month names, an entry's title), Caveat only for short margin notes (the time between milestones, cassette labels), VT323 only for the decorative `DateStamp` on photos; everything you read or tap is the system font. Icons are custom template SVGs in the asset catalog (`icon.*`: timeline, camera, library, note, voice, ribbon/ribbon.fill, postmark, hourglass, dial, play, delete); system controls keep SF Symbols. Shared pieces live in `Views/AlbumParts.swift` (`Ribbon`, `AlbumTabs`, `CassetteView`, `Postmark`, `NotesSection` on `LetterPaper`, `Arrival`) and `Theme.swift` (`DateStamp`, `LetterPaper`, `Tape`, `printShadow()`). Every form is a `PaperForm`, which also gives its keyboard a hide key and interactive dismissal; `KeyboardDismissal` (installed on the windows in `RootView.onAppear`) hides the keyboard on any tap outside a text field. The tint is set three ways: the `AccentColor` asset, `.tint(.darkroom)` on `RootView`, and the window's UIKit `tintColor` in `RootView.onAppear`; the navigation bar's paper background and serif titles are set in `MomentsApp.init`.
- App icon and launch screen: the milestones thread (three marigold pins on an S-shaped thread in the darkroom accent). `AppIcon.appiconset` holds light, dark and tinted 1024-point PNGs drawn by `scripts/render-icon.swift` (edit the design there and rerun it, from the repo root); the launch screen (`UILaunchScreen` in `project.yml`) is the same mark, `LaunchMark` (SVG, light and dark), centred on `Paper`.
- Timeline rows (`EntryRow`): photos and videos are tilted prints (tilt from `uuid`, so it is stable) with the `DateStamp`; voice memos are cassette cards; notes are letters with the text on the lines. Milestones carry a marigold `Ribbon`. The `List` is `.plain` (grouped styles clip prints into cards) with month headings as rows, not section headers (plain lists pin headers on a dark band). The floating dock at the bottom (a frosted pill, no band behind it) has camera, note, voice memo and library one tap away (`TimelineView.add`, which asks for location access first, except for imports), and the shutter in the middle opens `AddMomentSheet` (four tiles, the current place), which hands its choice to `TimelineView.openPicked` once dismissed. Motion, all with a Reduce Motion fallback (a short fade or nothing): a print added on this device (`Arrival.mark` at insert) drops in and develops from washed-out; the milestones thread draws itself and pins each milestone (`MilestoneRail`, staggered by `index`); marking a milestone drops the ribbon with a light haptic; the date stamp flickers on in an entry's details; the cassette's reels turn only while audio plays or records (`CassetteView`).
- Tips are taken on the app's website, not in the app (no StoreKit). `RootView.website` is its URL (GitHub Pages, from `docs/`); when set, the title menu shows "About Moments", which opens it in an in-app Safari view (`SafariView`). Keep that label neutral, never "tip" or "donate": outside the US, App Store rules forbid apps from pointing to payments outside in-app purchase.
- The website is `docs/` (static HTML; `style.css` uses the design system's tokens): `index.html` has the support FAQ and the Ko-fi link, `privacy.html` is the App Store privacy policy. Keep both true to the app: when it starts storing, sending or asking permission for something new, update the policy and its date. Preview with the `website` entry in `.claude/launch.json`.
- Languages: English (development language) and Italian. UI strings live in `Moments/Localizable.xcstrings`, permission prompts in `Moments/InfoPlist.xcstrings` (keyed by the Info.plist key), both kept by hand with `extractionState: manual` (XcodeGen projects don't update catalogs on build). Every new user-facing string needs an Italian entry there: SwiftUI literals (`Text`, `Button`, `Label`, `accessibilityLabel`…) are looked up automatically; strings built in code need `String(localized:)`, as in `AlbumMode.title`, `Milestones.swift` and the default timeline's name. Elapsed times come from `DateComponentsFormatter` (`Elapsed`), and dates from the formatters, so they follow the language by themselves. Italian copy uses the typographic apostrophe (’). To check for missing keys, build with `SWIFT_EMIT_LOC_STRINGS=YES` and compare the `.stringsdata` keys with the catalog; to try Italian, set the simulator's language or the scheme's App Language.
- Deleting entries or timelines leaves Photos assets and albums in Photos; everything else lives in the store, so deleting the model is enough.
