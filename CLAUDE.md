# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Moments is a private SwiftUI iOS app (iOS 17+, iPhone only) for keeping multiple timelines of photos, videos, notes and voice memos. Any entry can be a milestone; a milestones view shows them on a line with the time between them. No third-party dependencies and no tests yet.

## Build

The Xcode project is generated by XcodeGen from `project.yml` at the repo root. Edit `project.yml` for target settings, Info.plist keys (mostly `INFOPLIST_KEY_*` build settings; `Moments/Info.plist` and `Moments/Moments.entitlements` are generated from its `info:` and `entitlements:` sections) and permission strings, then regenerate. Don't hand-edit `Moments.xcodeproj`. New Swift files under `Moments/` are picked up on regeneration. The app version is `MARKETING_VERSION` and the build number `CURRENT_PROJECT_VERSION` in `project.yml`; the timeline settings screen shows both at the bottom. TestFlight uploads go through `bundle exec fastlane beta` (`fastlane/Fastfile`, with fastlane pinned by the `Gemfile`; setup in the README; `skip_build:true` re-uploads the last `build/Moments.ipa`), which passes the next build number as `CURRENT_PROJECT_VERSION`, so `project.yml` only needs a bump for a new marketing version.

```bash
xcodegen
```

```bash
xcodebuild -project Moments.xcodeproj -scheme Moments -destination 'generic/platform=iOS Simulator' build
```

The camera needs a real device; on the simulator `CameraView` falls back to the photo library. For location, set one with `xcrun simctl location <device> set <lat>,<lon>`; `xcrun simctl privacy <device> reset location it.vincendep.moments` brings the consent prompt back.

iCloud sync needs a paid team: `DEVELOPMENT_TEAM` and the bundle ID in `project.yml` are the owner's (change both to build under another account) (the CloudKit container is `iCloud.$(PRODUCT_BUNDLE_IDENTIFIER)`). Simulator builds work without a team; without an iCloud account the store just stays local (the log shows `CKAccountStatusNoAccount`).

## Architecture

SwiftData holds three models: `Timeline` (name, settings) with a cascading to-many `entries` relationship to `Entry`, which has a cascading to-many `media` relationship to `MediaItem` (`Models/MediaItem.swift`): any mix of photos, videos and voice memos, ordered by `sortIndex` (CloudKit has no ordered relationships; read them through `Entry.sortedMedia`, `prints`, `voiceMemos` and `cover`, the first print). The store syncs to the user's private iCloud database through CloudKit (the default `ModelConfiguration`, `.automatic`, picks up the entitlement), so a new phone gets everything back. Media:

- **Photos/videos** are saved to the system Photos library via `PhotoService`, never copied into the app. `MediaItem.assetLocalID` is the `PHAsset` ID on the device that added it; `assetCloudID` (`PHCloudIdentifier`) is the same on every device with iCloud Photos. Always get an asset's ID through `PhotoService.localID(for:)`, which falls back to the cloud ID and never writes back (each device has its own local IDs). Importing from the library links existing assets (`PhotoService.assets(for:)`, oldest first, and `item(for:)`), using the oldest asset's creation date as the entry date; picking several asks whether they make one moment or one each (`TimelineView.importItems`).
- **Voice memos** are recorded to a temp file by `AudioService` and stored in `MediaItem.audioData` (`.externalStorage`), so they sync with the store.
- **Titles, notes and metadata** live in SwiftData.

Things to keep in mind:

- Which Photos album new media goes into is a per-timeline setting stored on `Timeline` (`albumModeRaw` with a computed `albumMode: AlbumMode` — `.perTimeline` / `.shared` / `.none` — plus `addImportsToAlbum`). `PhotoService.album(for:)` resolves the album; per-timeline album IDs are kept per device in `UserDefaults` (`PhotoService.albumID(for:)`, keyed by `Timeline.uuid`), because a synced local ID would make devices overwrite each other; another device finds the album by title, as it arrives through iCloud Photos. Albums are renamed with the timeline.
- Every entry has a `title` (optional; `displayTitle` falls back to `dateLabel`) and `text`, shown as Notes (the whole content for entries without media). Time of day is optional: when `hasTime` is false, `date` is kept at the start of the day (`DateTimeRow` enforces this). `DateTimeRow` shows the time beside the date, with no toggle: a clock button sets one (now's time of day) and a clear button drops it.
- Location: `Entry.latitude`/`longitude`/`placeName`, read and set together as `Entry.place` (`Models/Place.swift`). The system consent prompt is the only switch, with no in-app setting: `TimelineView.present(_:)` asks once (`LocationService.requestAccess()`) before the first capture sheet opens, and with access new notes, voice memos and camera captures get the current place (`LocationService.current()`, reverse-geocoded by `CLGeocoder`); camera captures also write it to the Photos asset, since the system camera picker saves none. Library imports never use the current location: they take `PHAsset.location`, named after inserting. `WhenWhereSection` (the small map with its postmark, then `DateTimeRow`, then the place's name or "Add Location", in one section) is on every entry's details and in the note and voice editors; the place row pushes `LocationPicker` (Apple Maps search via `MKLocalSearchCompleter`, "Current Location" only with access, "Remove Location"), so places can be added without location access. Rows don't show the place.
- Milestones: `Entry.isMilestone`, toggled by the ribbon button beside the "⋯" menu in `EntryDetailView`'s toolbar (outlined in red, filled in marigold when on) or by a leading swipe on a row. The list only flags milestone rows (and `DayScrubber` dots milestone days); `EntryDetailView` has no list of other milestones. Helpers (`Timeline.milestones`, oldest first, and the elapsed strings) are in `Models/Milestones.swift`. Once a timeline has a milestone, `TimelineView` shows "All | Milestones" album divider tabs (`AlbumTabs`). Each tab is its own `List` (`EntriesList`, `MilestonesList` in `Views/TimelineLists.swift`, sharing `TimelineRow`), both kept alive in a `ZStack` and hidden by opacity, so each keeps its own scroll position; the Milestones list is only created on its first visit, so its thread draws in when first seen. The Milestones view lists only milestones, without month headers or scrubber, each row with its full date and the time since the first milestone (`Entry.sinceFirstMilestone(_:)`, passed to `EntryRow` as `elapsed`). A `MilestoneRail` marigold thread joins them, pinned at each milestone, and between each pair the time between them is handwritten in `.pencil` beside an hourglass (`Entry.interval(since:)`); its rows use `milestoneRailRow()` (no vertical insets or separators) so the line is unbroken, and delete by trailing swipe since the interval rows rule out `onDelete`.
- `Entry.kind` (`EntryKind`) is how an entry is shown, worked out from its media: a print when it has a photo or video (the cover's kind), a cassette when it only has voice memos, a letter otherwise. `Entry.add(_:)`, `remove(_:)` and `makeCover(_:)` change the media and set `modifiedAt`. An entry used to hold one photo, video or voice memo in `kindRaw`, `assetLocalID`, `assetCloudID` and `audioData`; those fields stay (renaming a synced attribute would leave the CloudKit data behind) but only `MediaMigration` reads them: at launch and on becoming active it moves them into a `MediaItem` (with the entry's `uuid`) and clears them, `kindRaw` "" marking an entry as done. CloudKit rules apply to the models: every property needs a default or must be optional, relationships must be optional, and no `@Attribute(.unique)`. Entries have a stable `uuid` and `modifiedAt` (set on edit), groundwork for merging timelines from another person via export/import.
- `PhotoService.backfillCloudIDs(in:)` runs on launch once Photos access is granted, since a fresh capture only gets an iCloud ID once it reaches iCloud.
- On first launch `RootView` creates a default "My Timeline" (guarded by the `"seededDefaultTimeline"` `@AppStorage` flag, so it isn't recreated after the user deletes it). On a new phone it is created before iCloud delivers the user's timelines, so `removeRedundantDefaultTimeline()` deletes it while untouched once older timelines appear.
- Navigation: `RootView` shows the current timeline full screen (`"lastTimelineID"` `@AppStorage`, matched against `Timeline.uuid`, falling back to the first). There is no list screen: the navigation title's menu (`toolbarTitleMenu`, which needs an inline title) switches timelines and offers "New Timeline…". The gear opens `TimelineEditorView`, the single per-timeline screen for name, media settings and deletion (it also creates timelines). `TimelineView` groups entries by month, always newest first, and opens at the top; the Milestones view is the opposite, oldest first, so it reads from "Start". Nothing else scrolls automatically except a new entry, which scrolls All to the top to show it. `DayScrubber` on the right edge jumps to any day with entries (days spaced evenly, year labels); it fades in while scrolling, detected with a simultaneous `DragGesture` on the `List` since iOS 17 has no scroll-offset callback, and jumps via `ScrollViewProxy`. It presents the capture sheets from a bottom-center floating add button. Each capture view takes the timeline and inserts its own `Entry`. Tapping a row pushes `EntryDetailView`, which shows the media (one taped print, or several on swipeable pages, each a `PrintPage` loading its own photo or `VideoPlayer`; voice memos below as `CassetteCard`s, or the big `CassetteView` when a single memo is all there is), adds more and deletes the entry from the "⋯" menu top right ("Add to This Moment": camera, library, or `VoiceRecorderView` with `adding:`, none of which change the entry's date or place; then "Delete Entry"), removes them or makes a print the cover from a "⋯" button (`ItemActions`, in a print's bottom border and on each memo card), and edits title, notes, date/time and place in place via `@Bindable`, saving on disappear. Its title field heads the page, above the media; the media is the header of a section without rows, since a form clips rows to their rounded cards (which would cut the tape, and prints sliding past the margin) but not headers, and a long press doesn't reach a header, hence the buttons. Several prints page edge to edge (`bleed`), each print aligned with the form's content; the navigation bar shows the title only once that field has scrolled away (`TitleSection`'s `scrolledAway`). `TitleSection` (title field with the date as placeholder) and `WhenWhereSection` are shared by it, `NoteEditorView` and `VoiceRecorderView`.
- Design system ("The Family Album": album paper, white prints, darkroom red; mockups at https://claude.ai/artifact/8HkXzsDHQu1B7kAqf8udyk; the older token reference at https://claude.ai/artifact/9zbESFb8q5AHoCbwrgW3rb predates it). `Views/Theme.swift` holds the colours (asset-catalog sets with a darkroom-brown dark mode: `.darkroom` accent, `.darkroomFill`, `.marigold` for milestones only, `.postmark` for places, `.pencil` for margin notes, `.paper`, `.card` (print white), `.ink`, `.tab`, `.rule`, `.dateStamp`, `.shadow`, `.onDarkroom`) and fonts; never hard-code a colour or point size, and use `.shadow` (never `.ink`) for shadows so dark mode doesn't glow. Fonts are bundled in `Moments/Fonts` (SIL OFL, licences beside them, registered via `UIAppFonts` in `project.yml`) and reached through `AlbumFont`, which scales with Dynamic Type: Fraunces (soft, regular weight) only for headings (timeline name in the nav bar, italic month names, an entry's title), Caveat only for short margin notes (the time between milestones, cassette labels), VT323 only for the decorative `DateStamp` on photos; everything you read or tap is the system font. Icons are custom template SVGs in the asset catalog (`icon.*`: timeline, camera, library, note, voice, ribbon/ribbon.fill, postmark, hourglass, dial, play, delete); system controls keep SF Symbols. Shared pieces live in `Views/AlbumParts.swift` (`Ribbon`, `AlbumTabs`, `CassetteView`, `CassetteCard`, `Postmark`, `NotesSection` on `LetterPaper`, `Arrival`) and `Theme.swift` (`DateStamp`, `LetterPaper`, `Tape`, `printShadow()`). Every form is a `PaperForm`, which also gives its keyboard a hide key and interactive dismissal; `KeyboardDismissal` (installed on the windows in `RootView.onAppear`) hides the keyboard on any tap outside a text field. The tint is set three ways: the `AccentColor` asset, `.tint(.darkroom)` on `RootView`, and the window's UIKit `tintColor` in `RootView.onAppear`; the navigation bar's paper background and serif titles are set in `MomentsApp.init`.
- App icon and launch screen: the milestones thread (three marigold pins on an S-shaped thread in the darkroom accent). `AppIcon.appiconset` holds light, dark and tinted 1024-point PNGs drawn by `scripts/render-icon.swift` (edit the design there and rerun it, from the repo root); the launch screen (`UILaunchScreen` in `project.yml`) is the same mark, `LaunchMark` (SVG, light and dark), centred on `Paper`.
- Timeline rows (`EntryRow`): entries with photos or videos are a tilted print of the cover (tilt from `uuid`, so it is stable) with the `DateStamp`; with more prints, blank prints peek out beneath it (only the cover is loaded) and "+2" is pencilled beside it; voice memos are a cassette tile tucked under its corner that plays the first. Entries with only voice memos are cassette cards; notes are letters with the text on the lines. Milestones carry a marigold `Ribbon`. The `List` is `.plain` (grouped styles clip prints into cards) with month headings as rows, not section headers (plain lists pin headers on a dark band). The floating dock at the bottom (a frosted pill, no band behind it) has camera, note, voice memo and library one tap away (`TimelineView.add`, which asks for location access first, except for imports), and the shutter in the middle opens `AddMomentSheet` (four tiles, the current place), which hands its choice to `TimelineView.openPicked` once dismissed. Motion, all with a Reduce Motion fallback (a short fade or nothing): a print added on this device (`Arrival.mark` at insert) drops in and develops from washed-out; the milestones thread draws itself and pins each milestone (`MilestoneRail`, staggered by `index`); marking a milestone drops the ribbon with a light haptic; the date stamp flickers on in an entry's details; the cassette's reels turn only while audio plays or records (`CassetteView`).
- Tips are taken on the app's website, not in the app (no StoreKit). `RootView.website` is its URL (GitHub Pages, from `docs/`); when set, the title menu shows "About Moments", which opens it in an in-app Safari view (`SafariView`). Keep that label neutral, never "tip" or "donate": outside the US, App Store rules forbid apps from pointing to payments outside in-app purchase.
- The website is `docs/` (static HTML; `style.css` uses the design system's tokens): `index.html` has the support FAQ and the Ko-fi link, `privacy.html` is the App Store privacy policy. Keep both true to the app: when it starts storing, sending or asking permission for something new, update the policy and its date. Preview with the `website` entry in `.claude/launch.json`.
- Languages: English (development language) and Italian. UI strings live in `Moments/Localizable.xcstrings`, permission prompts in `Moments/InfoPlist.xcstrings` (keyed by the Info.plist key), both kept by hand with `extractionState: manual` (XcodeGen projects don't update catalogs on build). Every new user-facing string needs an Italian entry there: SwiftUI literals (`Text`, `Button`, `Label`, `accessibilityLabel`…) are looked up automatically; strings built in code need `String(localized:)`, as in `AlbumMode.title`, `Milestones.swift` and the default timeline's name. Elapsed times come from `DateComponentsFormatter` (`Elapsed`), and dates from the formatters, so they follow the language by themselves. Italian copy uses the typographic apostrophe (’). To check for missing keys, build with `SWIFT_EMIT_LOC_STRINGS=YES` and compare the `.stringsdata` keys with the catalog; to try Italian, set the simulator's language or the scheme's App Language.
- Deleting entries or timelines leaves Photos assets and albums in Photos; everything else lives in the store, so deleting the model is enough.
